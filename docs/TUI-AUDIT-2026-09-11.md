# CLI / terminal audit — 2026-09-11

Release: `@quaivault/cli@0.7.0`. SDK dependency remains `@quaivault/sdk@0.6.1`.

## Findings addressed

- Signing delegation lost explicitly selected profile/identity and dry-run settings.
  The child now receives these as literal global arguments, without unattended
  approval flags. Signing remains in the one-shot command.
- Ink listener detachment did not reliably stop Node's pending native stdin read.
  PTY testing reproduced missing child input. Handoff now waits for Ink's current
  readable callback to finish, then pauses stdin before spawning. Acknowledgement
  uses raw mode, restores the prior mode, and handles stream closure/errors.
- Overlapping scoped reads could display one vault's data under another's label.
  Requests have generation guards; reducer events carry their vault address.
  Independent pane failures report stale/unavailable data without discarding other
  successful reads. Shutdown invalidates outstanding scoped work.
- A removed transaction could change the open detail's action target. Details now
  close on removal; recovery actions disarm until another request is selected.
- Long details, owner sets, recovery data and assets were clipped without navigation.
  Content scrolls with arrows, j/k, paging keys and Home/End. Table viewports and
  responsive chrome stay within the terminal; field focus remains visible at 40×12.
- Policy typing could trigger refresh; early Enter could submit before the final
  field. Text buffers and overlays now own their input. Last-field Enter alone builds.
- Uniform 128-character paste limits blocked real calldata and owner lists while
  typed input was unbounded. Both paths now use field-specific limits and visible
  rejection, plus cursor editing and Unicode-aware display widths.
- ERC-20 forms silently relied on 18 decimals. Decimals are now required explicitly.
- Missing TUI workflows now include ABI-assisted calls, ERC-1155 receiver data,
  common proposal timing/retry options, all pending recovery requests, indexed
  deposit/token-transfer/recovery history, and full receive address, delegatecall
  whitelist, and signed-message views.
- SDK-default pagination silently limited discovery and pending lists to 50 rows.
  These now page with explicit resource bounds; history loads additional pages on
  demand, including past the SDK's 200-row single-request maximum.
- Bounded affordance fan-out, realtime debounce, subscription coverage for deposit,
  transfer and signed-message events, and a 15-second reconciliation poll improve
  stability under event bursts.

## Verification

- Typecheck, strict lint, build, renderer/reducer/workflow/SDK-contract tests pass.
- Full suite on Node 22: 546 tests, including all four built-binary JSON contracts.
  The managed local Node 26 environment passes 542 and skips those four because
  its synchronous subprocess probe is restricted; they were run on Node 22.
- Synthetic PTY sessions exercise Kitty protocol negotiation and CSI-u Enter,
  standard xterm input, and tmux TERM fallback. Checks cover detail/help scrolling,
  child input delivery, single-key return, bracketed paste, resize from 80×24 to
  40×12, normal exit, alternate-screen cleanup, paste-mode cleanup, and restored
  canonical/echo settings. The regression runner is checked in and runs in CI.
- npm production vulnerability audit: zero findings.
- Website CLI overview/reference updated for 0.7.0; lint and production build pass.

## Scope and limits

- These are PTY/protocol tests, not GUI sessions inside installed Kitty, iTerm2,
  Windows Terminal or a running tmux server. No graphics protocol, custom font,
  clipboard injection or terminal-specific configuration is required. Normal text
  selection is retained by leaving mouse reporting disabled.
- Discovery is capped at 1,000 vaults per role; pending reads at 1,000 per vault.
  Reaching a cap produces a visible incomplete-data warning. History is paged on
  demand. Offset pagination over a moving indexer is not an atomic snapshot.
- No funded transactions or real passwords are used by these tests. The child
  remains responsible for fresh chain reads, disclosure, confirmation and signing.
- Key import/export/removal, contacts, aliases and diagnostics retain their
  one-shot surfaces. Policy editing is available in the TUI.

Protocol reference: [Kitty keyboard protocol](https://sw.kovidgoyal.net/kitty/keyboard-protocol/).
Terminal lifecycle and capability detection use the installed Ink 7.1.1 APIs.
